# QA: безопасность входа и пароли (порт MedConnect 10.10) — 2026-10-11

Объект проверки: изменения, перенесённые из MedConnect:
- реальный IP клиента за прокси;
- блокировка аккаунта после серии неудачных входов;
- срок жизни и одноразовость ссылки сброса пароля;
- запрет служебных полей пользователя;
- пароли пользователей в админке (ссылка на почту, новый пароль, свой пароль);
- экранирование имён в письмах.

Стенд изолированный: пустая база, Strapi на `:1351` с `IS_PROXIED=true` и `PROXY_MAX_IPS_COUNT=1`, Vite на `:1343`. Почта уходит в локальную SMTP-заглушку. Пользователи синтетические, реальные аккаунты и прод не затрагивались.

Прогоны делались **на двух СУБД**: SQLite (как локально) и PostgreSQL 16 (как на проде). Каждый набор запускался на свежей базе. Языки интерфейса: ru, en, kk. Ширина экрана: 390 и 1366.

## Что проверено и подтверждено

- **IP за прокси.** В журнал и в лимиты попадает адрес, дописанный прокси, а не тот, что прислал клиент. Подмена первого адреса не обходит лимит входа, а соседний клиент за тем же прокси не страдает. IPv6, пустой, мусорный и очень длинный заголовок — без 500.
- **Блокировка.**
  - Один общий счётчик для входа по email, email в верхнем регистре, логину, телефону и телефону с 8.
  - Закрытый аккаунт отвечает 429 на любой из этих вариантов, `Retry-After` около 900 секунд.
  - Ошибки старше 60 минут не копятся. Блокировка длится 15 минут и снимается сама.
  - Успешный вход обнуляет счётчик.
  - «Почта не подтверждена» с верным паролем не считается ошибкой, неверный пароль — считается.
  - Сброс по ссылке и пароль от админа снимают блокировку.
  - Письмо о блокировке уходит на языке пользователя.
- **Ссылка сброса.**
  - «Забыли пароль?» — 1 час, ссылка от админа — 24 часа.
  - Истёкшая ссылка даёт `reset_link_expired`, токен стирается. Ссылки без срока, выданные до выкатки, считаются истёкшими.
  - Новая ссылка гасит старую. Смена пароля админом и смена в профиле тоже гасят ссылку.
  - Слабый пароль по ссылке отклоняется, и ссылка при этом не сгорает.
  - Объект вместо кода отклоняется.
  - После сброса старые сессии получают 401.
- **Служебные поля.**
  - `resetPasswordToken`, `confirmationToken`, `tokenValidAfter` и поля блокировки отклоняются в `PUT` и `POST /api/users` на любом слое тела.
  - `PUT /users/me` их молча игнорирует, регистрация не сохраняет.
  - Фильтры, сортировка, `fields` и `populate` по этим полям (в том числе анонимно через `/api/doctors`) отвечают `400 Invalid key` или не меняют выборку. Значения наружу не попадают.
- **Пароли админом.**
  - Менеджер, врач, пациент и аноним получают 401 или 403.
  - Мусорный id и `documentId` в пути — 404.
  - Слабый пароль, не строка, пробелы по краям, больше 72 байт — 400. Тело 2 МБ — 413.
  - В базе хранится bcrypt.
  - После смены сессии пользователя завершаются, старый пароль не работает. Уведомление приходит без пароля.
  - Когда почта недоступна: ссылка даёт честный `502 email_send_failed`, смена пароля — `notified: false`. «Забыли пароль?» при этом отвечает тем же 200, что и для несуществующего адреса, — наличие аккаунта не раскрывается.
- **XSS.** HTML и `<img onerror>` в ФИО экранируются в письмах и не исполняются в списке пользователей и в окне «Пароль».
- **Ошибки и инъекции.** Массив, объект, число, 20 000 символов и SQL-пейлоад вместо логина или пароля дают 4xx, никогда 500 или 200. Битый JSON — тоже 4xx.

## Что не покрыто

- Настоящий Traefik перед Strapi: прокси имитировался заголовком. После выкатки проверьте IP в строке `LOGIN_FAILURE` (см. `DEPLOYMENT.md`).
- Доставка через настоящий Yandex SMTP.
- Разрыв уже открытых WebSocket-соединений сигналинга после смены пароля: HTTP-сессии проверены, сокеты — нет.
- Сценарий в «Врачах», когда карточка сохранилась, а новый пароль сервер отклонил.

## Для MedConnect

Дефекты B1, B2 и B4 по коду есть и в MedConnect: там та же проверка тела `bodyOf`, тот же подсчёт ошибок через `nextFailureState` и тот же штатный `resetPassword` без атомарного захвата ссылки. На стенде MedConnect не проверялось. B3 там нет: заблокированному MedConnect отвечает раньше.

## Как перезапустить

Перед запуском соберите сервер: `cd server && npx strapi build`.

Для режима `pg` нужен одноразовый Postgres на `127.0.0.1:5544`:

```bash
PG=/opt/homebrew/opt/postgresql@16/bin
$PG/initdb -D /tmp/qa-pg -U qa --auth=trust
$PG/pg_ctl -D /tmp/qa-pg -o "-p 5544 -k ''" start
```

Запуск наборов:

```bash
cd qa-artifacts/login-security-2026-10-11
./stand.sh sqlite && node security.mjs sqlite "$PWD"   # свежий стенд на каждый набор
./stand.sh sqlite && node attacks.mjs sqlite "$PWD"
./stand.sh pg && node attacks.mjs pg "$PWD"
# UI: свежий стенд и Vite на 1343
./stand.sh sqlite
(cd ../../frontend && VITE_API_URL=http://localhost:1351 npx vite --port 1343 --strictPort &)
node ui.mjs
```
